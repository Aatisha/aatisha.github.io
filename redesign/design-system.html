Design system

Everything the site is built from, in one place. Typography and colour each have options to choose between; once they’re picked, they become the tokens every page uses.

Overview

Quiet window, loud world. One white page held up against a photograph, photos treated like prints, and type and colour that step back so the work can lead.

01 — Principles

How it should feel

Frame

A window onto a place

Each key screen is a large rounded white window floating on a full-bleed, grainy photograph.

Objects

Photos are prints

White borders, soft shadows and slight tilts. They stack, fan and lift when you reach for them.

Voice

Three voices, used on purpose

Grotesk for UI, an editorial serif for statements, handwriting for asides. Never more than two on a screen.

Air

Whitespace is the material

Tiny labels, generous margins. Colour comes from the photographs; the interface stays neutral.

Typography · Decided: B · Sans + serif accent

One type system for every page.

Today each page sets its own type, so the site reads like several sites. This page does three things: it shows what’s inconsistent now, sets the roles and rules every page will share, and lets you compare five type systems on real content from the portfolio. Pick one, and it becomes the single source for every page.

What the guideline fixes, whichever system you pick

  • One page-title style on every page, home to postcard.
  • Twelve roles, one size each, fluid between phone and desktop. No one-off sizes.
  • 17px for reading, 15px for interface. Nothing else for body text.
  • 11px is the floor. The 8–10px labels move up to 11.
  • Two weights in sans: 400 to read, 500 to emphasise. 600 only for the brand mark.
  • Real italics, loaded on purpose, never synthesised.
  • The same fonts loaded on every page, from one link.
  • Caveat only on objects: polaroids, postcards and notes. Never a heading.

    05 · After you pick

    How it gets applied

    1. Tokens. The chosen system becomes role tokens in tokens.css (--type-display-*, --type-h1-* … --type-hand-*), replacing the seven size tokens.
    2. One font link. Every page loads the same families and weights, including Geist’s real italic.
    3. Role classes. Page titles, section titles, card titles, subheads, body, captions and labels across all pages switch to the roles, and the 41 one-off sizes in styles.css go.
    4. Page titles line up. Home, About, Playground and Postcard get the same Display as the case studies, with their lead underneath.
    5. Small text grows. The 8–10px labels on the postcard and tags move to 11px; Georgia goes.
    6. Checked page by page on desktop and phone before anything is committed.

    Contrast today

      What the guideline fixes, whichever palette you pick

      • Fourteen named roles, and every colour on the site maps to one of them. No raw hex in components.
      • Every text colour passes AA: secondary text 6.5:1 or more, the lightest text 4.5:1 or more.
      • Accent split in two: a fill for shapes and marks, and a darker accent for text, so both stay readable.
      • One off-white for panels, one for tiles. The eight variants go.
      • Lines from ink: one hairline and one stronger line, both tinted from the text colour.
      • Dark mode built in: every role has a dark value, so the About page’s “lights out” uses the same system.
      • Environment colours stay fixed: the sea, sand and photographs are content, not theme.
      • Accent is rare: counts, focus, one tag per block and the quote rule. Never a background for long text.

          Shape · Applied

          Same size, same corners, same shadow, everywhere.

          Spacing, corners, borders and shadows now follow one scale each, set in tokens.css and used across every page. Unlike type and colour there’s nothing to choose here: this tab records what was inconsistent, what each step is for, and the rules that keep it that way.

          01 · Audit

          What was inconsistent, and what changed

          • 11 → 7corner sizes on the rendered pages, now one scale of seven
          • 3 → 1corner sizes for tags (3, 4 and 999px)
          • 10 → 5shadows, now five named levels (only the Instagram replica keeps its own)
          • 3 → 1tag paddings, plus one chip size and one button height
          • Paper is paper. Polaroids, the postcard, ticket, luggage tag and stamp sheet were 0, 3 and 6px; all now share 4px corners.
          • Tags match. Case-card tags, research tags and “From insight” tags were three shapes and four paddings; now one.
          • Screens are framed alike. Only some case-study screenshots had a hairline; now every one does, so white UI never melts into the page.
          • Floating things float alike. The “Read case study” label and the before/after handle share one shadow.
          • Objects rest and lift alike. The postcard and stamp sheet used their own warm shadows; they now use Lift and Photo.
          • One hairline. Fifteen hand-written 1px lines now use the same hairline token.

          02 · Corners

          Roundness grows with size

          Small things get small corners, big things get big ones. Anything inside a rounded box takes the box’s radius minus the gap, so the corners run parallel.

          08 · Rules

          Keeping it consistent

          • Tokens onlyNo raw radius, border width or shadow in a component. If a new one seems needed, it joins the scale first.
          • Size picks the cornerPick the radius by how big the thing is on screen, not by what it is.
          • Nest cornersInner radius = outer radius − the gap. Never the same radius inside and out.
          • Screens get a hairline, photos don’tScreenshots and clips get the hairline; photographs and prints get a white border and a shadow instead.
          • Shadow means heightUse the level that matches how high the thing sits. Hover moves one level up.
          • Objects are the exceptionPolaroids, the postcard and other paper props may tune their padding, but use the shared corner and shadow.
